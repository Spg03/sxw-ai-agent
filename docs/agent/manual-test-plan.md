# AgentForge 手工验收清单（2026-09-25）

适用范围：本次权限、Hermes 审核与恢复、评测队列、附件及前端错误提示改造。请先在**测试环境**使用虚构账号与非敏感文件；不要用生产数据库、真实简历或公开截图里的令牌。每项记录「通过 / 失败 / 未测」、浏览器 Network 响应、后端 `requestId/traceId` 与复现步骤。功能失败时不应出现“已完成”的假成功提示。

## 0. 环境与自动化基线

1. 使用 JDK 21、Node/npm、PostgreSQL（带 `vector`、`pg_trgm` 扩展）、Redis、MinIO；需要实际 AI 回复时再配置 DashScope 密钥/可用的模型。按本地配置启动后端（默认 `http://localhost:8123`），在 `frontend` 运行 `npm ci`、`npm run dev`，打开 `http://localhost:5173`。Vite 把 `/api` 代理至后端。检查 `/api/health`、登录、刷新页面后会话是否正常。若后端无法启动，先记录启动异常，后续 UI 项标记“阻塞”，不要算失败。
2. 在 `frontend` 执行 `npm test`、`npm run lint`、`npm run build`、`npm audit --audit-level=high`；预期测试与构建成功、无高危依赖漏洞。当前 `AuthContext.tsx` 有一个既有 Fast Refresh 警告，需单独记录，不能把它说成 lint 零警告。
3. 在仓库根目录用 JDK 21 执行 `mvn -B -ntp verify -Dskip.frontend=true -Ddependency-check.skip=true -Djacoco.append=false`。预期构建成功、单测无失败、JaCoCo 行覆盖率不低于 40%。`dependency-check.skip` 表示**未**做在线 OWASP 依赖扫描。
4. 数据库专项必须用**可丢弃且库名以 `_test` 结尾**的 PostgreSQL，不要填业务库。PowerShell 示例（替换密码后在仓库根目录执行）：

   ```powershell
   $env:TEST_POSTGRES_URL = 'jdbc:postgresql://localhost:5432/agentforge_test'
   $env:TEST_POSTGRES_USER = 'postgres'
   $env:TEST_POSTGRES_PASSWORD = '<仅测试库密码>'
   mvn -B -ntp -Dskip.frontend=true -Ddependency-check.skip=true -Dtest=PostgresMigrationTest test
   ```

   预期 4 项全部执行且通过，**不是跳过**：全新迁移、V12 升级保留数据、刷新令牌并发单赢家、Hermes `NOWAIT` 锁。测试会创建并删除随机 schema；测试账号需要创建扩展/schema 的权限。GitHub Actions 的 `develop` 流水线也应确认这 4 项非跳过。不要为运行此项改动业务库配置。

## 1. 权限与用户隔离（优先级 P0）

准备两个普通用户 A/B；如有安全的测试账号，再准备 `EVALUATOR`、`ADMIN`。不要在生产库手工改角色。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| S1 | 不登录访问 `/api/conversations`、`/api/agent/traces`、`/api/hermes/candidates`、`/api/eval/cases` | 业务 API 返回未授权；公开健康检查仍可访问。浏览器不能仅因隐藏菜单就算通过。 |
| S2 | A 创建会话并发送测试消息；B 用自己的登录态访问 A 的会话、消息、附件列表/上传、会话记忆状态、Trace ID | B 均不能读写 A 数据；响应不能泄露私有内容。A 仍能正常访问自己的数据。 |
| S3 | A 在知识库/笔记创建含唯一测试词的私有内容；B 列表、搜索及聊天检索该词 | B 看不到 A 的私有内容。若文档显式设为全局共享，应按该范围单独验收，不要误判为隔离失败。 |
| S4 | 普通用户直接调用 Hermes 审核/管理 API 与评测 API；评测员调用评测和 Hermes；管理员调用两者 | 普通用户两者均拒绝；评测员仅评测允许；管理员两者允许。缺少角色账号时记“未测”。 |
| S5 | 登录后登出，用旧访问令牌请求受保护 API；禁用测试账号后重试已有令牌 | 旧令牌不可继续访问；禁用账号不可继续访问。不要把完整令牌写进验收报告。 |
| S6 | 同一刷新令牌几乎同时发起两次 `/api/auth/refresh`，再用旧令牌重试 | 并发恰好一次成功、一次失败；旧刷新令牌再次使用失败，不产生第二个有效令牌。此项可由数据库专项先验证，再做接口联调。 |

## 2. 附件与会话（优先级 P0）

使用虚构简历：TXT、MD、文字型 PDF、把关键信息放在**表格单元格**的 DOCX；再准备扫描型无文字 PDF、超过 10 MiB 的文件和不支持的格式。确保 MinIO 可用。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| A1 | 在 `/chat` 新会话分别上传四种有效文件，附一条“请概括文件里的独特测试词”消息发送 | 上传显示 READY，发送按钮可用；回答能引用测试词（模型质量另记）；DOCX 表格中的文字被提取。检验知识库文档与聊天附件是不同入口。 |
| A2 | 上传扫描型 PDF、空文件、超限文件及不支持格式 | 明确拒绝并提示原因；扫描件提示先 OCR，不出现 READY，也不留下可选附件。项目尚无 OCR。 |
| A3 | 选中已删除、别的会话、别的用户或未就绪附件，再发送；同时选一份正常附件和一份失效附件 | **整次请求失败**并提示重新选择，不可静默忽略坏附件后继续让模型回答。不存在与越权附件应使用不泄露归属的错误。 |
| A4 | 同一消息选 20 个附件与 21 个附件；重复选择同一 ID（若 UI 不允许，可用接口构造） | 20 个以内可进入处理；21 个明确拒绝；重复 ID 不造成重复引用。长材料可能按 24,000 字符上下文上限截断，不要求全文被模型看到。 |
| A5 | 上传后删除附件，再删除含附件的会话；观察元数据和 MinIO 对象 | 元数据不再可查询；后台清理最终移除对象。清理任务 5 分钟周期重试，故不要求即时物理删除；若清理失败需能看到待重试记录/日志。 |
| A6 | 停用或断开 MinIO 再上传；模型不可用时发送已上传附件 | UI 明确提示失败，不能显示“上传成功”或伪造回答；恢复服务后可重试。仅在隔离测试环境执行故障注入。 |

## 3. Hermes、评测和追踪（优先级 P1）

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| H1 | 管理员打开 `/hermes`，检查候选的来源 Trace、状态和内容；分别批准/拒绝不同测试候选 | 状态正确推进、记录审核人；重复点击不会重复应用。候选若不存在则记“未测”，不要在生产制造数据。 |
| H2 | 在测试环境制造应用失败/中断候选，查看失败列表并重试 | 可恢复失败状态；重试不会和仍在运行的原任务并发写入。无安全故障注入条件时记“未测”。 |
| E1 | 评测员在 `/eval` 新建一条用例，检查草稿状态；启用后运行单条测试 | 未启用前不可运行；提交运行后先显示 `PENDING` 并由后台推进，最终结果/报告可查看。先确认模型配额，避免批量调用。 |
| E2 | 提交未启用用例、其他 profile 的用例或超过 100 条用例 | 服务端拒绝；页面展示错误，不能仅依赖前端按钮禁用。 |
| T1 | A/B 各运行一次 Agent，对比 `/traces` 和直接 Trace API | 两人各只能看到自己的追踪；选中追踪可检查工具调用链/错误和耗时；历史无归属追踪仅管理员可查。 |

## 4. 会话、知识与故障体验（优先级 P1）

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| C1 | `/knowledge` 上传 TXT/MD 或粘贴文本，检索唯一测试词，再在聊天中选择相应知识文档提问 | 列表、检索、选择、发送均可操作；能区分“没有命中”和服务错误。知识库上传与聊天附件范围不同。 |
| C2 | 用正常消息走流式聊天；刷新页面重开该会话 | 流式内容逐步显示，结束状态正确；历史消息不重复、不丢失。连续快速发送或中断时记录是否出现重复回合/假完成。 |
| C3 | 断开模型或让后端返回非 JSON/5xx，再尝试上传或发送 | 页面展示可读的错误及 HTTP 状态，不把网关 HTML 原样显示给用户；失败消息不当作成功回答保存。 |
| C4 | 在工具已配置的测试账号下触发只读工具，再尝试需要批准的写操作 | Trace/审计中可定位工具调用；高风险工具未经批准不执行。若模型未生成工具调用，记录为“未测/缺陷待定位”，不要宣称工具链已完整通过。 |

## 5. 发布判定与回报格式

- **阻断发布**：P0 的越权访问、刷新令牌可重复消费、附件跨用户读取、混合有效/失效附件仍得到回答、迁移失败或数据丢失。
- **需明确记录**：P1 未测项、模型/对象存储不可用、PostgreSQL 专项跳过、Docker 未构建、依赖安全扫描未运行。不要把未测写成通过。
- 每条失败请反馈：`编号 | 环境/版本(commit) | 账号角色 | 操作 | 预期 | 实际 | HTTP 状态 | requestId/traceId | 已脱敏截图或日志`。不要贴 JWT、API Key、真实简历或数据库密码。
- 本地已完成的是 JDK 21 离线后端 verify（296 项中 4 项 PostgreSQL 条件跳过）、前端 4 项 API 测试/lint/build/npm audit；**真实 PostgreSQL、MinIO、模型与浏览器端到端仍待按本清单验收**。

生产 `application-prod.yml` 设有 `/api/v1` context path，与本地 Vite `/api` 代理不同；若测试 Docker/生产部署，请另外核对前端请求路径和反向代理规则，不要直接用本地地址代替生产验收。
