# 稳定性与权限修复说明

## 升级要求

- 发布时包含完整源码与 Flyway V13–V18；V18 新建附件清理队列表，不删除现有业务数据。既有迁移保持原样。
- 生产启动必须设置 `SXW_AUTH_JWT_SECRET`，至少 32 字节的高强度随机值。同一部署各实例使用相同值，重启时保持稳定；变更密钥会使旧访问令牌失效。实际密钥不要提交到仓库。
- Hermes 当前写入的是共享存储，审核页面及 API 仅允许 `ADMIN`。普通用户的个人记忆仍通过原有会话记忆接口管理。审核人由服务端获取，旧客户端携带的 `reviewedBy` 不再具有授权含义。
- 普通用户只能查询其现存会话的 Trace。无法确认归属的历史追踪仅管理员可查询。

## 行为变化

- 同一刷新令牌只能消费一次，并发失败请求不会产生新令牌。
- Hermes 使用原子审批、事务内行锁和应用回滚；失败可重试，超过 10 分钟仍处于批准状态的中断记录会进入恢复列表。恢复时若原应用仍在执行，不会抢占其写入。
- 评测用例先保存草稿，核对后点击启用。运行请求持久化为 PENDING 后立即返回，独立后台线程执行，页面自动刷新。仅允许所选助手的已启用用例，每次最多 100 个；中断任务不会自动重跑并产生重复模型费用。
- 附件先解析再上传；上传前登记兜底清理任务，成功入库后取消。删除附件/会话时，元数据删除与清理任务登记在同一事务中，物理文件由后台清理。失败任务每 5 分钟重试；清理队列不依赖会话外键。历史上已经遗失元数据的孤儿文件需另行核对，不会在本次升级中自动删除。

## 验证

- 后端：JDK 21，`mvn verify -Dskip.frontend=true -Ddependency-check.skip=true`（前端需先单独构建）。覆盖率门槛仍为 40%。
- 前端：在 `frontend` 执行 `npm ci`、`npm run lint`、`npm run build`、`npm audit --audit-level=high`。Windows 安装依赖前先关闭占用该目录的 Vite 服务。
- PostgreSQL 集成测试仅接受 `TEST_POSTGRES_URL` 指向名称以 `_test` 结尾的专用测试库，并读取 `TEST_POSTGRES_USER`、`TEST_POSTGRES_PASSWORD`。测试创建并清理随机 schema，不使用应用数据源。CI 提供临时 PgVector PostgreSQL，验证完整迁移、V12 升级、快照长版本号、追踪隔离和队列 SQL。
- 单元测试禁用定时任务；生产默认启用。不要在部署环境设置 `sxw.scheduling.enabled=false`，否则评测、附件清理及其他后台工作均不会执行。

发布版本需将关联源码、测试和迁移一并纳入同一提交，并按手工验收清单记录真实环境验证结果。

### 本轮行为修复

- 上传服务在解析及写对象存储之前校验会话归属；写元数据事务中继续保留带锁复查，防止上传期间会话被删除。
- 选中失效、未就绪、其他用户或其他会话的附件时，整个请求明确报错，不再忽略部分附件后继续回答。不存在与越权使用相同提示，避免暴露附件归属。
- 多附件按请求选择顺序构造上下文，重复 ID 去重；保留原有 20 个附件和 24000 字符上下文上限。该长度上限仍意味着长材料可能被截断，不代表全文都进入模型。
- 上传未提取到可读文字时拒绝入库，并提示扫描件先做 OCR；未新增 OCR 能力。历史 READY 但文本为空的附件也不再作为有效上下文使用。
- DOCX 按正文顺序读取段落和表格单元格（含嵌套表格），保留 30000 字符提取上限；尚不承诺读取图片、文本框、页眉页脚。
- 前端附件上传及流式请求准备失败时展示服务端具体说明；非 JSON 网关响应采用 HTTP 状态提示，不展示 HTML。
